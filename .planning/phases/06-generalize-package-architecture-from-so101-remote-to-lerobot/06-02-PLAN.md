<objective>
Extract robot, policy, and TCP teleoperation concerns into dedicated layers. This plan removes robot builders and action safety logic from the monolithic `teleop_tcp.py` shape and places them behind clearer package boundaries.
</objective>

<threat_model>
- T6-04: Splitting teleop code changes safety behavior. Mitigation: preserve exact error messages for leader read failure, first-action delta rejection, action key mismatch, and action value range checks where tests depend on them.
- T6-05: StarAI imports become eager and break test environments without hardware dependencies. Mitigation: keep all LeRobot/StarAI imports inside lazy loader functions.
- T6-06: Robot factory imports teleop runtime and creates circular imports. Mitigation: `robots/factory.py` may import robot-specific builders and type sets only; teleop client/server must not import robot builders.
</threat_model>
