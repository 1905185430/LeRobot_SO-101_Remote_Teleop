# Plan 07-02: Dataset Replay TCP Client Runtime

<objective>
Implement the dedicated local TCP dataset replay client that streams selected dataset action frames to the existing follower server, records replay artifacts, and aborts safely on failures.
</objective>

<must_haves>
- Implement D-01 through D-04, D-08 through D-21.
- Keep `scripts/run_teleop_follower.py` as the follower/server command.
- Add `scripts/run_dataset_replay_client.py`; do not overload `run_teleop_leader.py`.
- Preserve existing follower safety behavior and do not weaken safety limits.
- Fail fast on dataset, safety, TCP, ACK, timeout, and source-timing errors.
</must_haves>

<tasks>

## Task 1: Implement Dataset Replay TCP Client

<read_first>
- `lerobot_remote/teleop/client.py`
- `lerobot_remote/teleop/server.py`
- `lerobot_remote/network/protocol.py`
- `lerobot_remote/teleop/settings.py`
- `lerobot_remote/replay/dataset.py`
</read_first>

<action>
Create a focused dataset replay client under `lerobot_remote/replay/client.py`. It should iterate dataset frames, build ACTION messages with ordered frame IDs and dataset metadata tags, send them via the existing length-prefixed TCP protocol, validate ACKs, record RTT metrics, and sleep according to `fixed_hz` or validated source timestamps.
</action>

<acceptance_criteria>
- Fake dataset frames arrive at a fake follower server in order.
- ACK mismatches and TCP failures abort replay with no silent retry loop.
- Action values are normalized and range-validated before send.
- The existing follower still enforces key matching, first-action delta, and per-frame delta limiting.
</acceptance_criteria>

## Task 2: Wire Runtime Artifacts And Failure Events

<read_first>
- `lerobot_remote/runtime/teleoperation.py`
- `lerobot_remote/runtime/common.py`
- `lerobot_remote/recording/recorder.py`
- `lerobot_remote/reliability.py`
</read_first>

<action>
Add `run_dataset_replay_client(config)` under `lerobot_remote/runtime/dataset_replay.py`. It should create role `dataset-replay-client`, copy the resolved config, add dataset path/episode/frame/timing/endpoint/safety metadata, record start/complete/abort events, write summary, and close the recorder reliably.
</action>

<acceptance_criteria>
- Fake replay creates `metadata.json`, copied config, `events.jsonl`, metrics output, and `summary.md`.
- Metadata includes dataset path, episode, start/end frame, actual frame count, timing mode, replay frequency or source timing, TCP endpoint, and safety settings.
- Abort paths record an exception/abort event and still write a summary.
- Delta-limited follower behavior is visible in recorder output where the existing server reports it.
</acceptance_criteria>
